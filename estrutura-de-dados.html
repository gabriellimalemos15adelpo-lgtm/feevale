01

Fundamentos

Um array é uma estrutura de dados que armazena um conjunto de valores todos do mesmo tipo (int, double, char, boolean, String…). Por isso é chamado de estrutura homogênea.

Características que definem um array

  • Tamanho fixo: definido na criação e imutável. Para "aumentar", cria-se um array novo.
  • Alocação estática: ao declarar, você já indica o tamanho e o tipo.
  • Índice a partir de 0: o primeiro elemento é a posição 0 (zero-ésimo elemento); o último é tamanho − 1.
  • Posições contíguas na memória: os elementos ficam em sequência.
  • É um objeto: arrays são tipos por referência e criados com new.
Cai na prova

Um array de 12 elementos vai do índice 0 ao 11. O índice mais alto é sempre 1 a menos que o número de elementos. Confundir isso gera erro de "fora dos limites".

Declaração e criação

// dois passos: declara e depois aloca
int[] c;              // declara a variável de array
c = new int[12];      // cria o array com 12 posições

// tudo numa linha só
int[] c = new int[12];

Ao criar, cada posição recebe um valor padrão automático:

Tipo do arrayValor inicial padrão
int, double, float0 / 0.0
booleanfalse
String e outros objetosnull

Inicializando com valores (initializer)

// a lista entre chaves define os valores E o tamanho
int[] n = { 10, 20, 30, 40, 50 };  // tamanho 5, índices 0 a 4
String[] beatles = { "John", "Paul", "George", "Ringo" };

Acessando e percorrendo

Acesso direto pelo índice: vetor[0] devolve o primeiro valor. Para percorrer, usa-se um laço. A propriedade vetor.length devolve o número de elementos (é atributo, sem parênteses).

for (int i = 0; i < vetor.length; i++)
    System.out.println(vetor[i]);
Pegadinha comum

Em array é .length sem parênteses (é uma variável). Em String é .length() com parênteses (é método). E em ArrayList é .size(). Trocar isso é erro clássico de prova.

for-each (for aprimorado)

Percorre os elementos sem contador, evitando "pisar fora" do array. Limitação: serve só para ler os elementos — não consegue modificá-los nem dá acesso ao índice.

int total = 0;
for (int numero : array)   // "para cada numero em array"
    total += numero;
03

Tratamento de exceções

Se o código tentar acessar uma posição que não existe, o Java lança em tempo de execução a exceção ArrayIndexOutOfBoundsException.

Uma exceção indica um problema que ocorre durante a execução. O tratamento permite que o programa continue rodando em vez de travar.

Estrutura try / catch

try {
    // código que PODE lançar exceção
    ++frequency[responses[answer]];
}
catch (ArrayIndexOutOfBoundsException e) {
    // código que TRATA a exceção se ela ocorrer
    System.out.println(e);
}
  • O bloco try envolve o código de risco.
  • O bloco catch captura e trata o erro; declara um parâmetro (e) do tipo da exceção.
  • Se nada der errado no try, o catch é ignorado.
  • Pode haver vários catch para tipos diferentes de exceção.
Cai na prova

A validade do índice é verificada em tempo de execução, não de compilação. Um índice inválido só estoura quando o programa roda.

04

Passando arrays para métodos

Em Java, todos os argumentos são passados por valor. Mas o comportamento parece diferente entre tipos primitivos e arrays — e essa diferença é um tópico favorito de prova.

O que você passaO que o método recebeAltera o original?
Array inteiroCópia da referênciaSim — aponta pro mesmo objeto
Elemento primitivo (array[3])Cópia do valorNão — mexe só na cópia local
Por que isso acontece

Ao passar o array, copia-se a referência — dois nomes apontando para o mesmo objeto. Mudanças aparecem nos dois lados. Ao passar array[3] (um int), copia-se só o valor; a variável local morre quando o método termina e o original fica intacto.

Para passar um array como argumento, use só o nome, sem colchetes: modifyArray(temperaturas);. O cabeçalho do método declara o parâmetro como array: void modifyArray(double[] b).

05

Matrizes (arrays multidimensionais)

Uma matriz é um array com mais de uma dimensão. A bidimensional (2D) organiza dados em linhas e colunas, como uma tabela. Precisa de dois índices: a[linha][coluna].

Declaração e inicialização

// criação com new: 3 linhas x 4 colunas
int[][] b = new int[3][4];

// inicialização direta (valores agrupados por linha)
int[][] b = {{1, 2}, {3, 4}};

Percorrendo: for aninhado

O for externo controla as linhas; o interno, as colunas. Repare que array.length dá o número de linhas e array[linha].length dá o número de colunas daquela linha.

for (int linha = 0; linha < array.length; linha++) {
    for (int col = 0; col < array[linha].length; col++)
        System.out.printf("%d ", array[linha][col]);
}
Conceito-chave

No Java, uma matriz é na verdade um array de arrays. Por isso as linhas podem ter comprimentos diferentes (matriz irregular / "jagged"). Ex: {{1, 2}, {3, 4, 5}} — a linha 0 tem 2 colunas, a linha 1 tem 3.

Classe Arrays

A classe java.util.Arrays fornece métodos static prontos para operações comuns, evitando "reinventar a roda".

MétodoO que faz
sortOrdena o array (ordem crescente por padrão)
binarySearchProcura um valor num array já ordenado; devolve o índice

Duas pegadinhas juntas

1) binarySearch só funciona corretamente em array ordenado — passar um desordenado dá resultado indefinido.
2) Para comparar conteúdo use Arrays.equals(a, b). Usar a.equals(b) compara se são o mesmo objeto, não o conteúdo.

Para copiar elementos entre arrays existe também System.arraycopy(origem, iníc, destino, iníc, qtd).

07

ArrayList — o array dinâmico

O ArrayList (pacote java.util) resolve a maior limitação do array: o tamanho fixo. Ele cresce dinamicamente conforme você adiciona elementos.

O número que cai na prova

Quando o ArrayList enche, ele cria um array interno maior e copia tudo. O crescimento é de 50% do tamanho atual. Por baixo dos panos, ele é implementado com um array comum.

Declaração (classe genérica)

O <T> é um espaço reservado: você troca pelo tipo dos elementos. Só aceita tipos não primitivos (objetos) — por isso usa-se Integer, não int (o Java faz o "boxing" automático).

import java.util.ArrayList;

ArrayList<String> lista = new ArrayList<>();
ArrayList<Integer> numeros = new ArrayList<>();

Ao remover por índice, todos os elementos seguintes andam uma posição pra trás. Se você remove o índice 0, o que era índice 1 vira 0, o 2 vira 1, e assim por diante. 01

Lista Sequencial × Lista Encadeada

Para guardar vários itens na memória existem duas alternativas: um vetor sequencial (alocação estática) ou nodos ligados por ponteiros (alocação dinâmica). A primeira é a Lista Linear Sequencial; a segunda, a Lista Linear Encadeada.

 Lista Sequencial (array)Lista Encadeada
MemóriaContígua (blocos adjacentes)Não contígua (espalhada)
AlocaçãoEstática — tamanho definido em tempo de compilaçãoDinâmica — cresce/encolhe em tempo de execução
AcessoDireto pelo índice: v[3]Sequencial — precisa varrer nodo a nodo
DesperdícioSobra espaço se a previsão foi grande demaisSó ocupa o que está em uso
Conceito-chave

O problema que a lista encadeada resolve é o tamanho fixo do array: não é preciso prever quantos itens caberão. O preço pago é a perda do acesso direto por índice — não existe "posição 3" numa lista encadeada, só o caminho a partir do início.

02

O nodo e o cabeça da lista

Uma lista simplesmente encadeada é uma sequência conectada de elementos chamados nodos (ou nós). O nodo é o que se manipula: numa lista de alunos, o nodo é um aluno.

Composição do nodo

Todo nodo tem dois campos: a informação que ele guarda e um ponteiro para o próximo nodo da lista.

matrícula
5
nome
John
próximo
2200

O atributo cabeça

  • cabeca: variável que guarda o endereço de memória do primeiro nodo, ou seja, onde a lista começa. Fica na classe da lista, não no nodo.
  • Último nodo: tem o proximo apontando para NULL — é isso que indica o fim da lista.
  • Lista vazia: cabeca == null.
// cabeca: 1000
[1000] 5  John   -> [2200] 10 Paul -> [5000] 15 George -> NULL

Classe Aluno (o nodo)

public class Aluno {
    private int matricula;
    private String nome;
    private Aluno proximo;   // referência para outro Aluno

    public Aluno(int matricula, String nome) {
        this.matricula = matricula;
        this.nome = nome;
        this.proximo = null;    // nodo novo SEMPRE nasce com proximo = null
    }
    // + getters e setters dos três atributos
}
Cai na prova

O atributo proximo é do mesmo tipo da própria classe (Aluno dentro de Aluno). É essa auto-referência que permite o encadeamento. Ela guarda um endereço, não uma cópia do objeto.

A classe da lista

public class ListaSimplesmenteEncadeada {
    private Aluno cabeca;   // único atributo da lista

    public ListaSimplesmenteEncadeada(Aluno cabeca) {
        this.cabeca = cabeca;
    }
}

// criar a lista vazia, no App.java:
ListaSimplesmenteEncadeada lista = new ListaSimplesmenteEncadeada(null);
03

Inserção: no início e no final

Inserir no início custa três instruções e independe do tamanho da lista. Inserir no final exige varrer a lista inteira antes.

adicionarNoInicio() — 3 instruções

public void adicionarNoInicio(int matricula, String nome) {
    Aluno novo = new Aluno(matricula, nome);  // 1. cria o nodo (proximo = null)
    novo.setProximo(this.getCabeca());          // 2. novo aponta pro antigo primeiro
    this.setCabeca(novo);                      // 3. cabeca passa a ser o novo
}

Funciona igual com a lista vazia: se cabeca é null, o passo 2 apenas mantém novo.proximo = null — e o novo nodo vira o único da lista. Por isso este método não precisa de if.

Pegadinha comum

A ordem das duas últimas instruções importa. Se você fizer setCabeca(novo) antes de novo.setProximo(cabeca), o novo nodo passa a apontar para si mesmo e toda a lista antiga é perdida (ninguém mais guarda o endereço dela).

adicionarNoFinal() — precisa navegar até o fim

public void adicionarNoFinal(int matricula, String nome) {
    Aluno novo = new Aluno(matricula, nome);
    if (this.getCabeca() == null)          // lista vazia?
        this.setCabeca(novo);                // o novo é o cabeca
    else {
        Aluno AlunoAux = this.getCabeca();   // objeto auxiliar p/ navegar
        while (AlunoAux.getProximo() != null)
            AlunoAux = AlunoAux.getProximo();  // anda até o último nodo
        AlunoAux.setProximo(novo);             // o antigo último aponta pro novo
    }
}

O novo continua com proximo = null, o que é exatamente o correto para o último nodo. O objeto AlunoAux serve só para navegar — ele não cria nem copia nodo nenhum, apenas aponta para endereços que já existem.

Cai na prova

Repare na condição do while: é AlunoAux.getProximo() != null (para no último nodo), e não AlunoAux != null (que passaria do fim e daria erro). Essa diferença de uma palavra é clássica em prova.

Efeito prático no App.java

lista.adicionarNoInicio(5,  "John");
lista.adicionarNoInicio(10, "Paul");
lista.adicionarNoInicio(15, "George");
lista.adicionarNoFinal (20, "Ringo");
lista.adicionarNoFinal (25, "Pete");

// Resultado: George -> Paul -> John -> Ringo -> Pete -> NULL
Pegadinha comum

Inserir sempre no início inverte a ordem de inserção: John entrou primeiro e acabou em terceiro. Inserir no final preserva a ordem. Questões de prova adoram pedir "qual a lista final" depois de uma sequência mista dessas chamadas.

04

Busca e impressão

Ambas usam o mesmo padrão: um objeto auxiliar que parte do cabeca e caminha pelo proximo até achar o que quer ou bater em NULL.

buscarAluno() — devolve o endereço do nodo

public Aluno buscarAluno(int matricula) {
    Aluno AlunoAux = this.getCabeca();
    while (AlunoAux != null && AlunoAux.getMatricula() != matricula)
        AlunoAux = AlunoAux.getProximo();
    return AlunoAux;   // o nodo achado, ou null se não existir
}

O retorno é um objeto Aluno, ou seja, o endereço onde o nodo está na memória — quem chamou pode ler e alterar os dados dele à vontade. Se a matrícula não existir, o laço termina com AlunoAux == null e é null que volta.

Por que isso acontece

A ordem das condições no while não é decorativa: AlunoAux != null vem primeiro. O Java usa curto-circuito no && — se o primeiro teste é falso, o segundo nem é avaliado. Invertendo, chamaria getMatricula() sobre null e estouraria NullPointerException ao chegar no fim da lista.

imprimirLista() — varre tudo

public void imprimirLista() {
    Aluno AlunoAux = this.getCabeca();
    while (AlunoAux != null) {
        System.out.print(AlunoAux.getMatricula() + ": " + AlunoAux.getNome() + " -> ");
        AlunoAux = AlunoAux.getProximo();
    }
    System.out.print(" NULL ");
}

Aqui a condição é AlunoAux != null mesmo — a impressão precisa processar o último nodo e só então parar.

05

Remoção na lista simples

Remover é "costurar" a lista por cima do nodo excluído: o nodo anterior passa a apontar para o posterior. Para isso é preciso caminhar com dois ponteiros.

Os três casos que o método avalia

  1. Nodo não encontrado → o método não faz nada com a lista.
  2. É o primeiro nodo → o cabeca passa a ser o segundo nodo.
  3. É qualquer outro nodo → o anterior passa a apontar para o posterior do removido.
public void removerAluno(int matricula) {
    Aluno AlunoAux = this.getCabeca();      // aponta pro nodo avaliado
    Aluno AlunoAuxAnterior = null;           // aponta pro nodo de trás

    while (AlunoAux != null && AlunoAux.getMatricula() != matricula) {
        AlunoAuxAnterior = AlunoAux;             // o de trás vira o atual
        AlunoAux = AlunoAux.getProximo();        // e o atual avança
    }

    // caso 2: era o primeiro (o anterior nunca saiu do null)
    if (AlunoAuxAnterior == null) {
        this.setCabeca(AlunoAux.getProximo());
        return;
    }
    // caso 3: qualquer outro nodo
    if (AlunoAux != null)
        AlunoAuxAnterior.setProximo(AlunoAux.getProximo());
}
Conceito-chave

O teste que distingue os casos é AlunoAuxAnterior == null. Ele só continua null se o laço nunca deu uma volta, ou seja, se o nodo procurado já era o primeiro. É assim que o código sabe que precisa mexer no cabeca.

Removendo a matrícula 10 (Paul) de George → Paul → John: ao sair do laço, AlunoAuxAnterior aponta para George e AlunoAux para Paul. A instrução final faz o proximo de George pular para John, e Paul deixa de fazer parte da lista.

// antes:  George -> Paul -> John -> NULL
// depois: George --------> John -> NULL   // Paul fica inalcançável

Ninguém "apaga" o Paul da memória explicitamente: como nenhuma referência aponta mais para ele, o coletor de lixo do Java se encarrega disso.

Remoções mais simples

// remover o primeiro: basta o cabeca pular pro segundo
public void removerPrimeiroAluno() {
    if (this.getCabeca() != null) {
        Aluno AlunoAux = this.getCabeca();
        this.setCabeca(AlunoAux.getProximo());
    }
}

// remover todos: solta a referência do início e o resto vira lixo
public void removerTodosAlunos() {
    this.setCabeca(null);
}
Cai na prova

Para esvaziar a lista inteira basta uma linha: cabeca = null. Não é preciso percorrer nodo a nodo — perdida a referência do início, a corrente toda fica inacessível e o coletor de lixo recolhe.

06

Lista duplamente encadeada e o descritor

Na lista duplamente encadeada cada nodo guarda dois endereços: o do próximo e o do anterior. Isso permite varrer a lista nas duas direções.

anterior
NULL
matrícula
5
nome
John
próximo
2200
  • Dado um nodo qualquer ni, chega-se tanto ao ni−1 quanto ao ni+1.
  • O anterior do primeiro nodo aponta para NULL.
  • O proximo do último nodo aponta para NULL.

O descritor da lista — 3 atributos

A classe da lista dupla não guarda só o início. Ela mantém o que o material chama de descritor da lista:

AtributoTipoFunção
cabecaAlunoAponta para o primeiro nodo
caudaAlunoAponta para o último nodo

public ListaDuplamenteEncadeada() {
    this.cabeca  = null;
    this.cauda   = null;
    this.tamanho = 0;    // lista criada = lista vazia
}
Cai na prova

Cauda e tamanho não são exclusivos da lista dupla — dava para colocá-los também na simples. O que define uma lista como duplamente encadeada é o nodo ter o campo anterior. O descritor de três atributos é a estratégia adotada neste material, não uma obrigação teórica.

07

Operações na lista duplamente encadeada

Toda operação agora precisa manter quatro coisas coerentes: os ponteiros proximo, os ponteiros anterior, o cabeca/cauda e o tamanho.

adicionarNoInicio()

public void adicionarNoInicio(int matricula, String nome) {
    Aluno novo = new Aluno(matricula, nome);
    if (this.getCabeca() == null)              // lista vazia:
        this.setCauda(novo);                    // o novo também é a cauda
    else
        this.getCabeca().setAnterior(novo);     // o antigo 1º aponta pra trás

    novo.setProximo(this.getCabeca());
    novo.setAnterior(null);                     // é o 1º: nada antes dele
    this.setCabeca(novo);
    this.setTamanho(this.getTamanho() + 1);
}

adicionarNoFinal()

public void adicionarNoFinal(int matricula, String nome) {
    Aluno novo = new Aluno(matricula, nome);
    if (this.getCauda() == null)               // lista vazia:
        this.setCabeca(novo);                   // o novo também é o cabeca
    else
        this.getCauda().setProximo(novo);       // o antigo último aponta pro novo

    novo.setAnterior(this.getCauda());
    novo.setProximo(null);                      // é o último: nada depois
    this.setCauda(novo);
    this.setTamanho(this.getTamanho() + 1);
}
Conceito-chave

Os dois métodos são espelhados: inserindo no início, o if testa o cabeca e ajusta a cauda; inserindo no fim, testa a cauda e ajusta o cabeca. O motivo é o mesmo nos dois: quando a lista está vazia, o nodo inserido é ao mesmo tempo o primeiro e o último.

Cai na prova

Diferença crucial para a lista simples: inserir no final aqui é imediato, sem while nenhum, porque a cauda já guarda o endereço do último nodo. Na lista simples era preciso varrer a lista toda.

removerAluno() — agora com quatro ajustes

public void removerAluno(int matricula) {
    Aluno AlunoAux = this.getCabeca();
    Aluno AlunoAuxAnterior = null;
    while (AlunoAux != null && AlunoAux.getMatricula() != matricula) {
        AlunoAuxAnterior = AlunoAux;
        AlunoAux = AlunoAux.getProximo();
    }
    if (AlunoAuxAnterior == null) {               // era o primeiro
        this.setCabeca(AlunoAux.getProximo());
        AlunoAux.setAnterior(null);
        this.setTamanho(this.getTamanho() - 1);
        return;
    }
    if (AlunoAux != null) {                       // qualquer outro
        AlunoAuxAnterior.setProximo(AlunoAux.getProximo());
        if (AlunoAux.getProximo() != null)          // não era o último?
            AlunoAux.getProximo().setAnterior(AlunoAuxAnterior);
        this.setTamanho(this.getTamanho() - 1);
    }
}

Removendo John de Paul ⇄ John ⇄ George: o proximo de Paul passa a ser George, e o anterior de George passa a ser Paul. Os dois sentidos precisam ser costurados — esquecer o anterior quebra a impressão invertida.

Pegadinha comum

O if (AlunoAux.getProximo() != null) existe porque, se o nodo removido era o último, não há nodo posterior para ajustar o anterior — chamar setAnterior() sobre null daria NullPointerException.

Impressão nos dois sentidos

// do início para o fim: parte do cabeca, anda pelo proximo
Aluno AlunoAux = this.getCabeca();
while (AlunoAux != null) AlunoAux = AlunoAux.getProximo();

// do fim para o início: parte da cauda, anda pelo anterior
Aluno AlunoAux = this.getCauda();
while (AlunoAux != null) AlunoAux = AlunoAux.getAnterior();

A impressão invertida é a demonstração mais direta da vantagem da lista dupla: numa lista simplesmente encadeada ela seria inviável sem recursividade ou uma estrutura auxiliar.

Erros que aparecem em prova prática

  • Perder a lista: mexer no cabeca antes de guardar a referência do resto.
  • Esquecer o anterior: na lista dupla, ajustar só o proximo deixa a lista consistente numa direção e quebrada na outra.
  • Esquecer o tamanho: toda inserção soma 1 e toda remoção subtrai 1 — se um caminho do if não fizer isso, o descritor mente.
  • Condição de parada trocada: AlunoAux != null (varrer tudo) × AlunoAux.getProximo() != null (parar no último).

01

Pilha: a estrutura LIFO

A pilha é a estrutura em que só se mexe por uma ponta: o topo. Insere no topo, remove do topo.

LIFO e FILO — os dois nomes da mesma regra

  • LIFO (Last In, First Out): o último a entrar é o primeiro a sair.
  • FILO (First In, Last Out): o primeiro a entrar é o último a sair.

A analogia do material: livros empilhados numa caixa de mudança. O primeiro livro colocado fica no fundo e só sai por último; o último colocado é o primeiro a ser retirado.

Cai na prova

LIFO e FILO não são estruturas diferentes — são duas formas de descrever a mesma pilha, uma olhando pela entrada e outra pela saída. Questão de múltipla escolha adora oferecer as duas siglas como se fossem opostas.

Onde a pilha aparece na prática

  • Análise de expressões matemáticas (parênteses balanceados, notação pós-fixa).
  • Análise sintática em compiladores.
  • Pilha de execução (call stack) dos programas — cada método só enxerga as variáveis locais que estão no topo.
  • Operações de desfazer/refazer (undo/redo).

Uma pilha pode ser implementada com vetor (alocação estática, é o caso deste roteiro) ou encadeada (alocação dinâmica, como no roteiro 02).

02

Pilha sequencial: os dois atributos

Na versão sequencial, a classe Pilha guarda apenas um vetor e um inteiro.

AtributoFunção

Conceito-chave

O topo aponta para a próxima posição livre, não para o último elemento. Por isso o elemento que está no topo da pilha fica em pilha[topo - 1]. Errar esse "−1" é o erro número um deste roteiro.

Os dois estados-limite

  • Pilha vazia: topo == 0.
  • Pilha cheia: topo == tamanho máximo do vetor.
public class Pilha {
    private int topo;
    private Carta pilha[];

    public Pilha(int tamanho) {
        this.topo = 0;                     // pilha nasce vazia
        this.pilha = new Carta[tamanho];  // capacidade fixa
    }
}

No exemplo do roteiro, a pilha guarda objetos Carta (número de 1 a 13 + naipe: C copas, O ouros, E espadas, F flores) — o cenário é uma pilha de cartas de baralho, como no jogo Paciência.

  • Buscar o elemento do topo

03

push() e pop()

As duas operações que definem a pilha. Ambas devolvem um sinal de sucesso/fracasso em vez de quebrar o programa.

push() — empilhar

public boolean push(int numero, String naipe) {
    if (this.getTopo() < this.pilha.length) {   // tem espaço?
        Carta novo = new Carta(numero, naipe);
        this.pilha[this.getTopo()] = novo;         // grava NA posição topo
        this.topo++;                              // e só então avança
        return true;
    }
    else
        return false;                             // pilha cheia
}

A ordem é sempre grava e depois incrementa. O retorno boolean permite que quem chamou avise o usuário — é o que o App.java faz com a mensagem "A pilha atingiu o limite".

pop() — desempilhar

public Carta pop() {
    if (this.getTopo() != 0) {                    // pilha não está vazia?
        Carta nodoTopo = new Carta(this.pilha[this.topo-1]);
        this.setTopo(this.getTopo()-1);           // decrementa o topo
        return nodoTopo;                          // devolve quem saiu
    }
    else
        return null;                              // pilha vazia
}
Por que isso acontece

O pop() não apaga nada do vetor — ele só recua o topo em uma unidade. O dado antigo continua fisicamente na memória, mas passa a ser inalcançável e será sobrescrito no próximo push(). Remover, numa pilha sequencial, é mover um índice.

Impressão: do topo para a base

for (int i = this.getTopo()-1; i >= 0; i--)
    System.out.print(pilha[i].getNumero() + ": " + pilha[i].getNaipe() + " -> ");

O laço é decrescente, começando em topo-1. Por isso a saída aparece na ordem inversa da inserção.

Rastreando o exemplo do roteiro

// pilha com capacidade 4
push(5,"C"); push(8,"E"); push(9,"O"); push(2,"F");
push(3,"C");  // retorna false -> "A pilha atingiu o limite."

// impressão (topo -> base): 2:F -> 9:O -> 8:E -> 5:C
pop();     // remove o 2 de flores; novo topo passa a ser o 9:O
Cai na prova

A primeira carta empilhada (5:C) fica na base e só sairia por último — LIFO na prática. E o quinto push() falha silenciosamente se ninguém testar o retorno: o método devolve false, não lança exceção.

04

Fila: a estrutura FIFO

A fila mexe pelas duas pontas: entra pelo fim, sai pelo início. É a fila do refeitório, literalmente.

  • FIFO (First In, First Out): o primeiro a entrar é o primeiro a sair.
  • Toda informação que chega é inserida no final da fila.
  • Toda informação que sai (é consumida) é removida do início.

Onde a fila aparece na prática

  • Impressora organizando documentos na ordem de envio.
  • Consumo de processos de comunicação em redes.
  • Sistema operacional atendendo processos requisitados.

Como a pilha, a fila pode ser sequencial (vetor) ou encadeada. Este roteiro trata da sequencial.

Conceito-chave

A diferença prática entre as duas estruturas: na pilha a ordem de saída é o inverso da ordem de entrada; na fila, a ordem de saída é a mesma da entrada.

enfileirar(), desenfileirar() e o problema da fila que anda

Enfileirar é simples. Desenfileirar tem duas estratégias — e a mais óbvia esconde um defeito grave que o roteiro faz questão de mostrar.

enfileirar() — entra pelo fim

public boolean enfileirar(int valor, String nome) {
    if (this.inicio >= 0 && !this.filaCheia()) {
        Aluno novo = new Aluno(valor, nome);
        this.fila[this.fim] = novo;   // grava NA posição fim
        this.fim++;                   // e depois avança
        return true;
    }
    else
        return false;                // fila cheia
}

Mesmo padrão do push(): grava, depois incrementa o índice.

Estratégia 1 — só avançar o início (a que tem problema)

// versão que aparece COMENTADA no código do roteiro
public Aluno desenfileirar() {
    if (this.inicio >= 0 && this.inicio < this.fila.length) {
        Aluno removido = new Aluno(this.fila[this.inicio]);
        this.inicio++;   // "remove" apenas empurrando o início
        return removido;
    }
    else return null;
}
Cai na prova

Esse é o defeito central do roteiro. O inicio só anda para frente e o fim nunca recua, então a fila vai encolhendo a cada atendimento. Depois de esvaziar uma fila de capacidade 4, inicio e fim estão os dois no limite: a fila está logicamente vazia mas não aceita ninguém (no exemplo, o aluno Brian não consegue entrar). O professor deixa isso como exercício a resolver.

Estratégia 2 — deslocar todo mundo (a que está ativa no código)

public Aluno desenfileirar() {
    if (this.fim > 0) {
        Aluno removido = new Aluno(this.fila[this.inicio]);
        for (int i = 0; i < this.fim-1; i++)
            this.fila[i] = this.fila[i+1];   // todos andam uma casa
        this.fim--;                            // o fim recua
        return removido;
    }
    else return null;
}

Aqui o elemento da posição 1 sobrescreve o da 0, o da 2 sobrescreve o da 1, e assim por diante. O inicio fica sempre em 0 e o fim recua — a fila não encolhe e o espaço é reaproveitado.

Conceito-chave

A troca é clara: a estratégia 1 remove em uma instrução mas desperdiça o vetor; a estratégia 2 reaproveita todo o espaço, mas custa um laço que percorre a fila inteira a cada remoção.

Rastreando o exemplo do roteiro

// fila com capacidade 4
enfileirar(5,"John"); enfileirar(10,"Paul");
enfileirar(15,"George"); enfileirar(20,"Ringo");
enfileirar(25,"Pete");   // false -> "A fila atingiu o limite."

// impressão: 5:John -> 10:Paul -> 15:George -> 20:Ringo
desenfileirar();  // sai John (o primeiro que entrou)

Repare no contraste com a pilha: aqui a impressão sai na mesma ordem da inserção, e quem sai primeiro é quem chegou primeiro.

01

A pilha de execução (call stack)

Antes de entender recursividade é preciso entender o que acontece na memória quando um método chama outro. Esse controle é feito por uma pilha — a mesma estrutura LIFO do roteiro 03.

Para que serve a stack

  • Guarda de onde partiu a chamada do método, para saber para onde voltar quando ele terminar.
  • Guarda o conteúdo das variáveis locais de cada método chamado.
  • Cada chamada gera um quadro de pilha (stack frame) empilhado no topo.

Rastreando o exemplo do roteiro

public static int B(int x, int y) { return x + y; }

public static int A(int i, int j, int k) {
    int x;
    x = B(i, j);      // A fica SUSPENSO esperando B
    x = x + k;
    return x;
}

public static void main(String args[]) {
    int i = 1, j = 2, k = 3, y;
    y = A(i, j, k);   // main fica SUSPENSO esperando A
    System.out.println("y: " + y);   // imprime 6
}
// evolução da pilha de execução:
[ main ]  →  [ A ]     →  [ B ]     →  [ A ]      →  [ main ]
             [ main ]     [ A ]        [ main ]      (fim)
                          [ main ]
                          B devolve 3   A devolve 6

Sequência: main chama A(1,2,3) e fica suspenso; A chama B(1,2) e fica suspenso; B resolve 1+2=3 e é desempilhado; A então faz 3+3=6, retorna e é desempilhado; main imprime 6.

Cai na prova

As variáveis i, j, k de main e as de A têm os mesmos nomes mas são porções de memória diferentes. Cada quadro de pilha tem suas próprias variáveis locais — nomes iguais em métodos diferentes não se comunicam.

Conceito-chave

O método em execução é sempre o do topo da pilha. Quem está embaixo está suspenso, esperando um retorno. É exatamente esse mecanismo que faz a recursividade funcionar.

02

Recursividade: caso base e passo recursivo

Um método recursivo é aquele que chama a si mesmo com uma versão menor do problema, até chegar a um caso que sabe resolver direto.

As duas partes obrigatórias

  • Caso base (ou ponto de parada): o caso mais simples, resolvido sem nova chamada. É ele que encerra a recursão.
  • Passo recursivo: divide o problema em uma parte que o método sabe resolver e outra parecida com o original, porém menor, resolvida por uma nova chamada a si mesmo.

É a estratégia de dividir para conquistar: cada chamada abre um novo quadro na pilha de execução enquanto a anterior continua suspensa. Ao atingir o caso base, os retornos sobem em cascata até a chamada original.

Cai na prova

Sem caso base — ou com um passo recursivo que não converge para ele — a recursão é infinita: a pilha de execução cresce até estourar (StackOverflowError). Toda função recursiva precisa das duas partes.

Relação de recorrência

Sempre que um problema pode ser escrito em função de si mesmo, existe uma relação de recorrência — e, com ela, um algoritmo recursivo quase pronto:

// fatorial
n! = n × (n-1)!        com  1! = 1

// Fibonacci
fib(n) = fib(n-1) + fib(n-2)   com  fib(1) = fib(2) = 1

A relação se transpõe quase literalmente para o código: o caso da definição vira o if do caso base, e a fórmula geral vira o return com a chamada recursiva.

03

Fatorial

O clássico para aprender recursividade. Por definição, 1! = 1, e cada fatorial é o número multiplicado pelo fatorial do antecessor.

1! = 1
2! = 2 × 1! = 2
3! = 3 × 2! = 6
4! = 4 × 3! = 24

Versão iterativa

public static long fatorialIterativo(int n) {
    int i;
    long fat = 1;
    for (i = n; i > 1; i--)
        fat *= i;          // acumula n × (n-1) × ... × 2
    return fat;
}

Versão recursiva

public static long fatorialRecursivo(int n) {
    if (n == 1)                          // CASO BASE
        return 1;
    else
        return n * fatorialRecursivo(n-1);  // PASSO RECURSIVO
}

Rastreando fatorialRecursivo(4) na pilha

// descida (empilhando):
fat(4) → 4 * fat(3)
         fat(3) → 3 * fat(2)
                  fat(2) → 2 * fat(1)
                           fat(1) → 1        // caso base, para aqui

// subida (desempilhando os retornos):
fat(1) = 1  →  fat(2) = 2*1 = 2  →  fat(3) = 3*2 = 6  →  fat(4) = 4*6 = 24
Conceito-chave

Note que nenhuma multiplicação é feita na descida. As chamadas ficam todas suspensas na pilha esperando; só quando o caso base devolve 1 é que os produtos são calculados, de dentro para fora.

O retorno é declarado long porque o fatorial cresce muito rápido — int estoura já em valores pequenos de n.

04

Série de Fibonacci

Série descoberta por Leonardo de Pisa a partir do estudo do crescimento de uma população de coelhos. Os dois primeiros termos valem 1; cada termo seguinte é a soma dos dois anteriores.

1, 1, 2, 3, 5, 8, 13, 21, 34, ...
     ↑  ↑  ↑
     |  |  fib(3) = fib(1) + fib(2) = 2

Curiosidade que o material destaca: dividindo um termo pelo anterior, a razão converge para a proporção áurea. A série aparece no mercado financeiro, na teoria dos jogos e em diversas configurações da natureza.

Versão iterativa

public static long fibonacciIterativo(int n) {
    long n_menos_1, n_menos_2, res = 0;
    if (n == 1 || n == 2)
        return 1;
    else {
        n_menos_1 = 1; n_menos_2 = 1;   // os dois termos conhecidos
        for (int i = 3; i <= n; i++) {
            res = n_menos_1 + n_menos_2;  // calcula o termo atual
            n_menos_1 = n_menos_2;        // e desloca a "janela"
            n_menos_2 = res;
        }
        return res;
    }
}

A versão iterativa mantém apenas duas variáveis auxiliares com os termos anteriores e vai deslocando essa janela a cada volta do laço.

Versão recursiva

public static long fibonacciRecursivo(int n) {
    if (n == 1 || n == 2)              // CASO BASE (são DOIS)
        return 1;
    else
        return fibonacciRecursivo(n-1) + fibonacciRecursivo(n-2);
}
Cai na prova

O Fibonacci recursivo tem duas chamadas recursivas no mesmo return — diferente do fatorial, que tem uma só. Isso faz o número de chamadas explodir exponencialmente: fib(n-2) é recalculado várias vezes do zero. Por isso o Deitel traz uma dica de desempenho recomendando evitar recursão no estilo Fibonacci.

Pegadinha comum

O caso base do Fibonacci cobre dois valores (n == 1 || n == 2), porque a série precisa de dois termos iniciais conhecidos para poder somar. Escrever só n == 1 gera recursão infinita ao chegar em fib(0).

A recursão custa mais: cada chamada empilha um quadro com suas variáveis locais. Em troca, ela costuma expressar o problema de forma muito mais próxima da definição matemática — compare as duas versões do Fibonacci e a diferença fica evidente.

06

Pesquisa sequencial × pesquisa binária

Para achar um valor num vetor há duas estratégias, e a diferença de eficiência aumenta conforme o espaço de busca cresce.

Pesquisa sequencial

public static int pesquisaSequencial(int vetor[], int num) {
    for (int i = 0; i < vetor.length; i++) {
        if (vetor[i] == num)
            return i;      // devolve o ÍNDICE onde achou
    }
    return -1;              // não existe no vetor
}

Varre do início ao fim testando um por um. Funciona sempre, mas fica lenta quando o vetor é grande.

Pesquisa binária

A cada iteração ela descarta metade do espaço de busca: calcula o meio, compara, e continua só na metade onde o valor pode estar.

Cai na prova

A pesquisa binária só pode ser usada se o vetor estiver ordenado. É a pré-condição obrigatória — sem ordenação, descartar metade do vetor não faz sentido nenhum.

Os três índices de controle

  • inicio — começa em 0.
  • fim — começa em vetor.length - 1.
  • meio — recalculado a cada iteração: (inicio + fim) / 2.
Pegadinha comum

A divisão de meio é inteira: (0+19)/2 dá 9,5, mas o resultado é 9 — o Java trunca, não arredonda. Isso é obrigatório, já que índices de vetor são inteiros.

07

Pesquisa binária: iterativa e recursiva

Versão iterativa

public static int pesquisaBinariaIterativa(int vetor[], int num,
                                            int inicio, int fim) {
    int meio;
    while (inicio <= fim) {              // ainda há espaço de busca
        meio = (inicio + fim) / 2;
        if (num == vetor[meio])
            return meio;                 // achou: devolve o índice
        else
            if (num > vetor[meio])
                inicio = meio + 1;        // procura à DIREITA
            else
                fim = meio - 1;           // procura à ESQUERDA
    }
    return -1;                          // não encontrado
}

Versão recursiva

public static int pesquisaBinariaRecursiva(int vetor[], int num,
                                            int inicio, int fim) {
    int meio;
    if (inicio <= fim) {
        meio = (inicio + fim) / 2;
        if (num == vetor[meio])
            return meio;
        else
            if (num > vetor[meio])
                return pesquisaBinariaRecursiva(vetor, num, meio + 1, fim);
            else
                return pesquisaBinariaRecursiva(vetor, num, inicio, meio - 1);
    }
    return -1;
}
Conceito-chave

As duas versões são quase idênticas. A diferença: a iterativa tem um while e reatribui inicio/fim; a recursiva troca o while por um if e passa os novos limites como parâmetros da chamada. O caso base é o mesmo teste: quando inicio ultrapassa fim, o valor não existe e retorna -1.

Rastreando o exemplo do roteiro

Vetor ordenado com 20 elementos (1, 5, 10, …, 95), inicio = 0, fim = 19, procurando o valor 70:

Iteraçãoiníciofimmeiovetor[meio]Ação
1ª01994545 < 70 → inicio = 10
2ª10191470encontrado → retorna 14

Duas comparações contra as quinze que a pesquisa sequencial precisaria. Num vetor com bilhões de elementos, a diferença deixa de ser detalhe.

Cai na prova

Os dois métodos retornam o índice onde o valor está (não o valor em si) e -1 quando não encontram. E lembre da regra de decisão: se o procurado é maior que o do meio, ele está à direita (inicio = meio+1); se é menor, está à esquerda (fim = meio-1).

01

O que significa ordenar?

Ordenar é colocar os elementos de um vetor em uma sequência definida, como crescente ou decrescente. Os três algoritmos deste roteiro modificam o próprio vetor e usam um laço externo para repetir uma operação sobre ele.

Nos exemplos, a entrada é [9, 8, 4, 2] e queremos chegar a [2, 4, 8, 9]. Cada estratégia garante uma parte diferente do vetor a cada passagem:

EstratégiaO que fica garantidoOperação central
BubbleO maior valor restante chega ao fim.Comparar vizinhos e trocar quando estão invertidos.
SelectionO menor valor restante chega ao início.Encontrar o índice do menor e trocar uma vez ao fim da busca.
InsertionA parte à esquerda continua ordenada.Deslocar os maiores e inserir a chave no espaço aberto.
Para não confundir

Bubble troca vizinhos durante a passagem; Selection procura o menor antes de trocar; Insertion guarda uma chave e desloca elementos para abrir espaço.

02

Bubble Sort: o maior “borbulha” para o fim

Compare vetor[j] com vetor[j+1]. Na ordem crescente, troque se o da esquerda for maior. Ao terminar uma passagem, o maior valor ainda não ordenado está na posição correta.

Rastreando [9, 8, 4, 2]

Início:      [9, 8, 4, 2]
1ª passagem: [8, 4, 2, 9]  // 9 chegou ao fim
2ª passagem: [4, 2, 8, 9]  // 8 chegou à penúltima posição
3ª passagem: [2, 4, 8, 9]  // resta apenas o primeiro elemento

O laço interno pode ficar menor a cada passagem: não é preciso comparar de novo a parte final já ordenada. No código entregue, i começa em 1 e j < vetor.length - i; assim, a primeira passagem compara até o último par e a seguinte para uma posição antes.

for (int i = 1; i < vetor.length; i++) {
    for (int j = 0; j < vetor.length - i; j++) {
        if (vetor[j] > vetor[j + 1]) {
            int aux = vetor[j];
            vetor[j] = vetor[j + 1];
            vetor[j + 1] = aux;
        }
    }
}

Quando pode parar antes?

Se uma passagem inteira ocorrer sem nenhuma troca, o vetor já está ordenado. A videoaula propõe uma flag para registrar trocas e sair cedo. No arquivo Java fornecido, porém, as linhas dessa otimização estão comentadas; a execução atual faz todas as passagens.

Custo

Com o limite interno reduzido, há (n−1) + (n−2) + ... + 1 = n(n−1)/2 comparações: O(n²) mesmo se o vetor já estiver ordenado. Com a parada por ausência de trocas corretamente ativada, o melhor caso cai para O(n); o pior continua O(n²).

03

Selection Sort: escolher o menor

Em cada passagem, considere i como início da parte ainda desordenada. Procure o índice do menor valor entre i e o fim; só depois da busca troque esse valor com vetor[i].

Rastreando [9, 8, 4, 2]

Início:      [9, 8, 4, 2]
i = 0:      [2, 8, 4, 9]  // menor = 2 (índice 3); troca com 9
i = 1:      [2, 4, 8, 9]  // menor restante = 4; troca com 8
i = 2:      [2, 4, 8, 9]  // 8 já está na posição correta
for (int i = 0; i < vetor.length; i++) {
    int menor = i;
    for (int j = i + 1; j < vetor.length; j++) {
        if (vetor[j] < vetor[menor]) menor = j;
    }
    int aux = vetor[menor];
    vetor[menor] = vetor[i];
    vetor[i] = aux;
}

menor guarda uma posição, não o número menor. O laço interno só atualiza esse índice; a troca acontece depois que a busca termina. O código fornecido ainda executa i = n−1, quando resta apenas um elemento e ocorre uma troca dele consigo mesmo. Parar em i < n−1 evita esse passo redundante.

Custo

A busca faz (n−1) + ... + 1 = n(n−1)/2 comparações tanto em vetor ordenado quanto invertido: O(n²) em ambos os casos. Há, no máximo, uma troca por passagem, embora a implementação fornecida também troque quando menor == i.

04

Insertion Sort: inserir a chave no lugar certo

Pense em organizar cartas na mão. Comece no segundo elemento: o único valor à esquerda já está ordenado. Guarde o valor atual em key, desloque para a direita os valores maiores e coloque a chave no espaço livre.

Rastreando [9, 8, 4, 2]

Início:      [9, 8, 4, 2]
Chave 8:    [8, 9, 4, 2]  // move 9; insere 8
Chave 4:    [4, 8, 9, 2]  // move 9 e 8; insere 4
Chave 2:    [2, 4, 8, 9]  // move 9, 8 e 4; insere 2
for (int j = 1; j < vetor.length; j++) {
    int key = vetor[j];
    int i = j - 1;
    while (i >= 0 && vetor[i] > key) {
        vetor[i + 1] = vetor[i]; // desloca, não troca
        i--;
    }
    vetor[i + 1] = key;   // preenche o espaço aberto
}

O while termina ao chegar ao início do vetor (i < 0) ou ao encontrar um elemento menor ou igual à chave. Nesse ponto, i+1 é a posição da inserção. Guardar key antes de deslocar impede que o valor original se perca.

Custo

Se o vetor já está ordenado, o while falha na primeira comparação de cada passagem: O(n). Na ordem inversa, cada chave percorre toda a parte esquerda: O(n²). Por isso é especialmente útil quando os dados estão quase ordenados.

Estável significa preservar a ordem relativa de registros que têm a mesma chave. No Bubble e no Insertion fornecidos, a condição estrita > não inverte elementos iguais; no Selection, a troca com um elemento distante pode inverter essa ordem.

A videoaula descreve uma progressão de eficiência entre Bubble, Selection e Insertion. Isso depende dos dados e do que se mede: os três ainda podem gastar O(n²). Selection costuma movimentar menos valores; Insertion se beneficia de entrada já ordenada ou quase ordenada.

Merge Sort: divisão, recursão e intercalação

Resumo do cap. 2 de Estruturas de dados (Ascencio e Araújo), dos slides do Prof. Juliano Varella de Carvalho, do código Java e da videoaula, seguido de flashcards.

1 · Dividir para conquistar 2 · Chamadas recursivas 3 · Intercalação 4 · Código Java 5 · Custo e comparação 6 · Atenção ao exemplo ★ Flashcards
01

Dividir para conquistar

O Merge Sort resolve a ordenação em três passos: dividir o intervalo em duas metades, ordenar cada metade recursivamente e combinar as duas metades ordenadas.

EtapaNo Merge Sort
DividirCalcular o meio q e separar os intervalos p..q e q+1..r.
ConquistarChamar mergesort para cada intervalo até restar um elemento.
CombinarUsar merge para intercalar duas partes já ordenadas.

Uma parte com um elemento já está ordenada. A divisão usa o mesmo vetor original: p, q e r delimitam partes lógicas. Vetores temporários são criados depois, durante a intercalação.

Pré-condição do merge

merge(A, p, q, r) só produz a parte A[p..r] ordenada se A[p..q] e A[q+1..r] já estiverem ordenadas. A recursão garante justamente essa condição.

02

As chamadas recursivas, passo a passo

O código recebe o vetor e os índices p (início) e r (fim). Enquanto p < r, calcula q = (p+r)/2 com divisão inteira, ordena a esquerda, ordena a direita e só então intercala.

void mergesort(int[] A, int p, int r) {
    if (p < r) {
        int q = (p + r) / 2;
        mergesort(A, p, q);       // ordena a esquerda
        mergesort(A, q + 1, r);   // ordena a direita
        merge(A, p, q, r);       // combina as duas
    }
}

Rastreando [9, 8, 4, 2]

mergesort(A, 0, 3) → q = 1
  esquerda 0..1 → [9] + [8] → merge → [8, 9]
  direita  2..3 → [4] + [2] → merge → [2, 4]
  merge final: [8, 9] + [2, 4] → [2, 4, 8, 9]

Na chamada (0,3), o meio é (0+3)/2 = 1 porque o Java descarta a parte fracionária. A chamada (0,1) divide em (0,0) e (1,1). Nessas partes p == r, o if é falso: esse é o caso base.

Como no roteiro 4, cada chamada fica na pilha de execução esperando as chamadas menores terminarem. A intercalação começa na volta da recursão: primeiro os pares, depois as metades maiores.

03

Como intercalar duas partes ordenadas

No código fornecido, merge(A, p, q, r) copia a metade esquerda para L e a direita para R. Dois índices, i e j, indicam o próximo valor de cada metade; k percorre as posições de A[p..r].

Se L[i] <= R[j], copie o valor da esquerda para A[k] e avance i. Caso contrário, copie o da direita e avance j. A comparação sempre escolhe o menor valor disponível, mantendo a saída em ordem.

Exemplo do merge final

Esquerda L = [8, 9]     Direita R = [2, 4]
compara 8 e 2 → copia 2
compara 8 e 4 → copia 4
direita acabou → copia 8 e 9
Resultado A[0..3] = [2, 4, 8, 9]

Os slides escrevem MERGE(A, p, q, r) com p ≤ q < r. O código Java guarda um espaço extra em cada vetor temporário: L[n1] e R[n2] recebem Integer.MAX_VALUE. Esses valores funcionam como sentinelas: quando uma metade real acaba, o valor máximo faz a outra metade ser escolhida.

int n1 = q - p + 1, n2 = r - q;
int[] L = new int[n1 + 1];
int[] R = new int[n2 + 1];
// após copiar os valores reais:
L[n1] = Integer.MAX_VALUE;
R[n2] = Integer.MAX_VALUE;
for (int k = p; k <= r; k++) {
    if (L[i] <= R[j]) A[k] = L[i++];
    else              A[k] = R[j++];
}
Limite da sentinela

O exemplo gera valores de 0 a 99, então Integer.MAX_VALUE é maior que todos eles. Para um vetor de int que possa conter o próprio Integer.MAX_VALUE, essa sentinela não é segura; nesse caso, use uma intercalação que teste explicitamente se i < n1 e j < n2.

04

Quem faz o quê no código Java?

PartePapel
mainCria o vetor, mostra os valores e chama mergesort(vetor, 0, vetor.length-1).
mergesort(A,p,r)Divide os intervalos, chama a si mesmo duas vezes e chama merge na volta.
merge(A,p,q,r)Intercala duas partes ordenadas usando os vetores temporários L e R.
montar / imprimirGeram números aleatórios de 0 a 99 e mostram o vetor; não participam da ordenação.

n1 = q-p+1 é a quantidade de elementos à esquerda; n2 = r-q é a quantidade à direita. O +1 aparece apenas em n1 porque o índice q pertence à metade esquerda.

Ordem das chamadas

Se merge fosse executado antes das duas chamadas recursivas, ele receberia metades ainda desordenadas e sua pré-condição falharia. A ordem correta é: esquerda, direita, intercalação.

05

Custo e comparação com o roteiro 5

Em cada nível da divisão, a intercalação percorre ao todo os n elementos: O(n). Dividir o intervalo ao meio gera cerca de log₂ n níveis. Assim, T(n) = 2T(n/2) + O(n) e o tempo total é O(n log n) no melhor, médio e pior caso.

AlgoritmoMelhor casoPior casoMemória extra
Bubble do códigoO(n²)O(n²)O(1)
SelectionO(n²)O(n²)O(1)
InsertionO(n)O(n²)O(1)
Merge SortO(n log n)O(n log n)O(n)

O Merge Sort precisa de vetores temporários para intercalar, além da pilha recursiva de profundidade O(log n). O espaço auxiliar total é O(n). Em compensação, seu pior caso cresce mais lentamente que o pior caso quadrático dos algoritmos do roteiro 5. Para poucos dados ou dados quase ordenados, o custo fixo de criar vetores e chamar métodos também importa.

Com a condição L[i] <= R[j], quando dois valores são iguais o algoritmo escolhe primeiro o da metade esquerda. Isso preserva a ordem relativa dos iguais: essa implementação é estável para entradas dentro do limite da sentinela.

  • System.out.println("*********** %s ***********\n" + msg) mostra %s literalmente. Para inserir a mensagem no cabeçalho, use System.out.printf("*********** %s ***********%n", msg).
