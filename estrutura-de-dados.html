01

Fundamentos

Um array é uma estrutura de dados que armazena um conjunto de valores todos do mesmo tipo (int, double, char, boolean, String…). Por isso é chamado de estrutura homogênea.

Características que definem um array

  • Tamanho fixo: definido na criação e imutável. Para "aumentar", cria-se um array novo.
  • Alocação estática: ao declarar, você já indica o tamanho e o tipo.
  • Índice a partir de 0: o primeiro elemento é a posição 0 (zero-ésimo elemento); o último é tamanho − 1.
  • Posições contíguas na memória: os elementos ficam em sequência.
  • É um objeto: arrays são tipos por referência e criados com new.
Cai na prova

Um array de 12 elementos vai do índice 0 ao 11. O índice mais alto é sempre 1 a menos que o número de elementos. Confundir isso gera erro de "fora dos limites".

Declaração e criação

// dois passos: declara e depois aloca
int[] c;              // declara a variável de array
c = new int[12];      // cria o array com 12 posições

// tudo numa linha só
int[] c = new int[12];

Ao criar, cada posição recebe um valor padrão automático:

Tipo do arrayValor inicial padrão
int, double, float0 / 0.0
booleanfalse
String e outros objetosnull

Inicializando com valores (initializer)

// a lista entre chaves define os valores E o tamanho
int[] n = { 10, 20, 30, 40, 50 };  // tamanho 5, índices 0 a 4
String[] beatles = { "John", "Paul", "George", "Ringo" };
02

Vetores (array 1D)

Um vetor é um array de uma única dimensão. Precisa de apenas um índice para acessar cada elemento.

0
5
1
10
2
15
3
20
4
25

Acessando e percorrendo

Acesso direto pelo índice: vetor[0] devolve o primeiro valor. Para percorrer, usa-se um laço. A propriedade vetor.length devolve o número de elementos (é atributo, sem parênteses).

for (int i = 0; i < vetor.length; i++)
    System.out.println(vetor[i]);
Pegadinha comum

Em array é .length sem parênteses (é uma variável). Em String é .length() com parênteses (é método). E em ArrayList é .size(). Trocar isso é erro clássico de prova.

for-each (for aprimorado)

Percorre os elementos sem contador, evitando "pisar fora" do array. Limitação: serve só para ler os elementos — não consegue modificá-los nem dá acesso ao índice.

int total = 0;
for (int numero : array)   // "para cada numero em array"
    total += numero;
03

Tratamento de exceções

Se o código tentar acessar uma posição que não existe, o Java lança em tempo de execução a exceção ArrayIndexOutOfBoundsException.

Uma exceção indica um problema que ocorre durante a execução. O tratamento permite que o programa continue rodando em vez de travar.

Estrutura try / catch

try {
    // código que PODE lançar exceção
    ++frequency[responses[answer]];
}
catch (ArrayIndexOutOfBoundsException e) {
    // código que TRATA a exceção se ela ocorrer
    System.out.println(e);
}
  • O bloco try envolve o código de risco.
  • O bloco catch captura e trata o erro; declara um parâmetro (e) do tipo da exceção.
  • Se nada der errado no try, o catch é ignorado.
  • Pode haver vários catch para tipos diferentes de exceção.
Cai na prova

A validade do índice é verificada em tempo de execução, não de compilação. Um índice inválido só estoura quando o programa roda.

04

Passando arrays para métodos

Em Java, todos os argumentos são passados por valor. Mas o comportamento parece diferente entre tipos primitivos e arrays — e essa diferença é um tópico favorito de prova.

O que você passaO que o método recebeAltera o original?
Array inteiroCópia da referênciaSim — aponta pro mesmo objeto
Elemento primitivo (array[3])Cópia do valorNão — mexe só na cópia local
Por que isso acontece

Ao passar o array, copia-se a referência — dois nomes apontando para o mesmo objeto. Mudanças aparecem nos dois lados. Ao passar array[3] (um int), copia-se só o valor; a variável local morre quando o método termina e o original fica intacto.

Para passar um array como argumento, use só o nome, sem colchetes: modifyArray(temperaturas);. O cabeçalho do método declara o parâmetro como array: void modifyArray(double[] b).

05

Matrizes (arrays multidimensionais)

Uma matriz é um array com mais de uma dimensão. A bidimensional (2D) organiza dados em linhas e colunas, como uma tabela. Precisa de dois índices: a[linha][coluna].

Declaração e inicialização

// criação com new: 3 linhas x 4 colunas
int[][] b = new int[3][4];

// inicialização direta (valores agrupados por linha)
int[][] b = {{1, 2}, {3, 4}};

Percorrendo: for aninhado

O for externo controla as linhas; o interno, as colunas. Repare que array.length dá o número de linhas e array[linha].length dá o número de colunas daquela linha.

for (int linha = 0; linha < array.length; linha++) {
    for (int col = 0; col < array[linha].length; col++)
        System.out.printf("%d ", array[linha][col]);
}
Conceito-chave

No Java, uma matriz é na verdade um array de arrays. Por isso as linhas podem ter comprimentos diferentes (matriz irregular / "jagged"). Ex: {{1, 2}, {3, 4, 5}} — a linha 0 tem 2 colunas, a linha 1 tem 3.

06

Classe Arrays

A classe java.util.Arrays fornece métodos static prontos para operações comuns, evitando "reinventar a roda".

MétodoO que faz
sortOrdena o array (ordem crescente por padrão)
binarySearchProcura um valor num array já ordenado; devolve o índice
equalsCompara se dois arrays têm os mesmos elementos na mesma ordem
fillPreenche o array com um mesmo valor
Duas pegadinhas juntas

1) binarySearch só funciona corretamente em array ordenado — passar um desordenado dá resultado indefinido.
2) Para comparar conteúdo use Arrays.equals(a, b). Usar a.equals(b) compara se são o mesmo objeto, não o conteúdo.

Para copiar elementos entre arrays existe também System.arraycopy(origem, iníc, destino, iníc, qtd).

07

ArrayList — o array dinâmico

O ArrayList (pacote java.util) resolve a maior limitação do array: o tamanho fixo. Ele cresce dinamicamente conforme você adiciona elementos.

O número que cai na prova

Quando o ArrayList enche, ele cria um array interno maior e copia tudo. O crescimento é de 50% do tamanho atual. Por baixo dos panos, ele é implementado com um array comum.

Declaração (classe genérica)

O <T> é um espaço reservado: você troca pelo tipo dos elementos. Só aceita tipos não primitivos (objetos) — por isso usa-se Integer, não int (o Java faz o "boxing" automático).

import java.util.ArrayList;

ArrayList<String> lista = new ArrayList<>();
ArrayList<Integer> numeros = new ArrayList<>();

Métodos principais

add(elem)Adiciona no final da lista
get(índice)Retorna o elemento naquela posição
remove(índice)Remove o elemento da posição indicada
size()Número de elementos (equivale ao .length do array)
contains(elem)true se o elemento existe na lista
indexOf(elem)Índice da primeira ocorrência do elemento

Cai na prova — reindexação

Ao remover por índice, todos os elementos seguintes andam uma posição pra trás. Se você remove o índice 0, o que era índice 1 vira 0, o 2 vira 1, e assim por diante. No exemplo da videoaula: removeu-se o "John" (índice 0), e depois get(2) passou a devolver o "Ringo", porque as posições se deslocaram.

01

Lista Sequencial × Lista Encadeada

Para guardar vários itens na memória existem duas alternativas: um vetor sequencial (alocação estática) ou nodos ligados por ponteiros (alocação dinâmica). A primeira é a Lista Linear Sequencial; a segunda, a Lista Linear Encadeada.

 Lista Sequencial (array)Lista Encadeada
MemóriaContígua (blocos adjacentes)Não contígua (espalhada)
AlocaçãoEstática — tamanho definido em tempo de compilaçãoDinâmica — cresce/encolhe em tempo de execução
AcessoDireto pelo índice: v[3]Sequencial — precisa varrer nodo a nodo
DesperdícioSobra espaço se a previsão foi grande demaisSó ocupa o que está em uso
Conceito-chave

O problema que a lista encadeada resolve é o tamanho fixo do array: não é preciso prever quantos itens caberão. O preço pago é a perda do acesso direto por índice — não existe "posição 3" numa lista encadeada, só o caminho a partir do início.

02

O nodo e o cabeça da lista

Uma lista simplesmente encadeada é uma sequência conectada de elementos chamados nodos (ou nós). O nodo é o que se manipula: numa lista de alunos, o nodo é um aluno.

Composição do nodo

Todo nodo tem dois campos: a informação que ele guarda e um ponteiro para o próximo nodo da lista.

matrícula
5
nome
John
próximo
2200

O atributo cabeça

  • cabeca: variável que guarda o endereço de memória do primeiro nodo, ou seja, onde a lista começa. Fica na classe da lista, não no nodo.
  • Último nodo: tem o proximo apontando para NULL — é isso que indica o fim da lista.
  • Lista vazia: cabeca == null.
// cabeca: 1000
[1000] 5  John   -> [2200] 10 Paul -> [5000] 15 George -> NULL

Classe Aluno (o nodo)

public class Aluno {
    private int matricula;
    private String nome;
    private Aluno proximo;   // referência para outro Aluno

    public Aluno(int matricula, String nome) {
        this.matricula = matricula;
        this.nome = nome;
        this.proximo = null;    // nodo novo SEMPRE nasce com proximo = null
    }
    // + getters e setters dos três atributos
}
Cai na prova

O atributo proximo é do mesmo tipo da própria classe (Aluno dentro de Aluno). É essa auto-referência que permite o encadeamento. Ela guarda um endereço, não uma cópia do objeto.

A classe da lista

public class ListaSimplesmenteEncadeada {
    private Aluno cabeca;   // único atributo da lista

    public ListaSimplesmenteEncadeada(Aluno cabeca) {
        this.cabeca = cabeca;
    }
}

// criar a lista vazia, no App.java:
ListaSimplesmenteEncadeada lista = new ListaSimplesmenteEncadeada(null);
03

Inserção: no início e no final

Inserir no início custa três instruções e independe do tamanho da lista. Inserir no final exige varrer a lista inteira antes.

adicionarNoInicio() — 3 instruções

public void adicionarNoInicio(int matricula, String nome) {
    Aluno novo = new Aluno(matricula, nome);  // 1. cria o nodo (proximo = null)
    novo.setProximo(this.getCabeca());          // 2. novo aponta pro antigo primeiro
    this.setCabeca(novo);                      // 3. cabeca passa a ser o novo
}

Funciona igual com a lista vazia: se cabeca é null, o passo 2 apenas mantém novo.proximo = null — e o novo nodo vira o único da lista. Por isso este método não precisa de if.

Pegadinha comum

A ordem das duas últimas instruções importa. Se você fizer setCabeca(novo) antes de novo.setProximo(cabeca), o novo nodo passa a apontar para si mesmo e toda a lista antiga é perdida (ninguém mais guarda o endereço dela).

adicionarNoFinal() — precisa navegar até o fim

public void adicionarNoFinal(int matricula, String nome) {
    Aluno novo = new Aluno(matricula, nome);
    if (this.getCabeca() == null)          // lista vazia?
        this.setCabeca(novo);                // o novo é o cabeca
    else {
        Aluno AlunoAux = this.getCabeca();   // objeto auxiliar p/ navegar
        while (AlunoAux.getProximo() != null)
            AlunoAux = AlunoAux.getProximo();  // anda até o último nodo
        AlunoAux.setProximo(novo);             // o antigo último aponta pro novo
    }
}

O novo continua com proximo = null, o que é exatamente o correto para o último nodo. O objeto AlunoAux serve só para navegar — ele não cria nem copia nodo nenhum, apenas aponta para endereços que já existem.

Cai na prova

Repare na condição do while: é AlunoAux.getProximo() != null (para no último nodo), e não AlunoAux != null (que passaria do fim e daria erro). Essa diferença de uma palavra é clássica em prova.

Efeito prático no App.java

lista.adicionarNoInicio(5,  "John");
lista.adicionarNoInicio(10, "Paul");
lista.adicionarNoInicio(15, "George");
lista.adicionarNoFinal (20, "Ringo");
lista.adicionarNoFinal (25, "Pete");

// Resultado: George -> Paul -> John -> Ringo -> Pete -> NULL
Pegadinha comum

Inserir sempre no início inverte a ordem de inserção: John entrou primeiro e acabou em terceiro. Inserir no final preserva a ordem. Questões de prova adoram pedir "qual a lista final" depois de uma sequência mista dessas chamadas.

04

Busca e impressão

Ambas usam o mesmo padrão: um objeto auxiliar que parte do cabeca e caminha pelo proximo até achar o que quer ou bater em NULL.

buscarAluno() — devolve o endereço do nodo

public Aluno buscarAluno(int matricula) {
    Aluno AlunoAux = this.getCabeca();
    while (AlunoAux != null && AlunoAux.getMatricula() != matricula)
        AlunoAux = AlunoAux.getProximo();
    return AlunoAux;   // o nodo achado, ou null se não existir
}

O retorno é um objeto Aluno, ou seja, o endereço onde o nodo está na memória — quem chamou pode ler e alterar os dados dele à vontade. Se a matrícula não existir, o laço termina com AlunoAux == null e é null que volta.

Por que isso acontece

A ordem das condições no while não é decorativa: AlunoAux != null vem primeiro. O Java usa curto-circuito no && — se o primeiro teste é falso, o segundo nem é avaliado. Invertendo, chamaria getMatricula() sobre null e estouraria NullPointerException ao chegar no fim da lista.

imprimirLista() — varre tudo

public void imprimirLista() {
    Aluno AlunoAux = this.getCabeca();
    while (AlunoAux != null) {
        System.out.print(AlunoAux.getMatricula() + ": " + AlunoAux.getNome() + " -> ");
        AlunoAux = AlunoAux.getProximo();
    }
    System.out.print(" NULL ");
}

Aqui a condição é AlunoAux != null mesmo — a impressão precisa processar o último nodo e só então parar.

05

Remoção na lista simples

Remover é "costurar" a lista por cima do nodo excluído: o nodo anterior passa a apontar para o posterior. Para isso é preciso caminhar com dois ponteiros.

Os três casos que o método avalia

  1. Nodo não encontrado → o método não faz nada com a lista.
  2. É o primeiro nodo → o cabeca passa a ser o segundo nodo.
  3. É qualquer outro nodo → o anterior passa a apontar para o posterior do removido.
public void removerAluno(int matricula) {
    Aluno AlunoAux = this.getCabeca();      // aponta pro nodo avaliado
    Aluno AlunoAuxAnterior = null;           // aponta pro nodo de trás

    while (AlunoAux != null && AlunoAux.getMatricula() != matricula) {
        AlunoAuxAnterior = AlunoAux;             // o de trás vira o atual
        AlunoAux = AlunoAux.getProximo();        // e o atual avança
    }

    // caso 2: era o primeiro (o anterior nunca saiu do null)
    if (AlunoAuxAnterior == null) {
        this.setCabeca(AlunoAux.getProximo());
        return;
    }
    // caso 3: qualquer outro nodo
    if (AlunoAux != null)
        AlunoAuxAnterior.setProximo(AlunoAux.getProximo());
}
Conceito-chave

O teste que distingue os casos é AlunoAuxAnterior == null. Ele só continua null se o laço nunca deu uma volta, ou seja, se o nodo procurado já era o primeiro. É assim que o código sabe que precisa mexer no cabeca.

Removendo a matrícula 10 (Paul) de George → Paul → John: ao sair do laço, AlunoAuxAnterior aponta para George e AlunoAux para Paul. A instrução final faz o proximo de George pular para John, e Paul deixa de fazer parte da lista.

// antes:  George -> Paul -> John -> NULL
// depois: George --------> John -> NULL   // Paul fica inalcançável

Ninguém "apaga" o Paul da memória explicitamente: como nenhuma referência aponta mais para ele, o coletor de lixo do Java se encarrega disso.

Remoções mais simples

// remover o primeiro: basta o cabeca pular pro segundo
public void removerPrimeiroAluno() {
    if (this.getCabeca() != null) {
        Aluno AlunoAux = this.getCabeca();
        this.setCabeca(AlunoAux.getProximo());
    }
}

// remover todos: solta a referência do início e o resto vira lixo
public void removerTodosAlunos() {
    this.setCabeca(null);
}
Cai na prova

Para esvaziar a lista inteira basta uma linha: cabeca = null. Não é preciso percorrer nodo a nodo — perdida a referência do início, a corrente toda fica inacessível e o coletor de lixo recolhe.

06

Lista duplamente encadeada e o descritor

Na lista duplamente encadeada cada nodo guarda dois endereços: o do próximo e o do anterior. Isso permite varrer a lista nas duas direções.

anterior
NULL
matrícula
5
nome
John
próximo
2200
  • Dado um nodo qualquer ni, chega-se tanto ao ni−1 quanto ao ni+1.
  • O anterior do primeiro nodo aponta para NULL.
  • O proximo do último nodo aponta para NULL.

O descritor da lista — 3 atributos

A classe da lista dupla não guarda só o início. Ela mantém o que o material chama de descritor da lista:

AtributoTipoFunção
cabecaAlunoAponta para o primeiro nodo
caudaAlunoAponta para o último nodo
tamanhointQuantidade de nodos da lista
public ListaDuplamenteEncadeada() {
    this.cabeca  = null;
    this.cauda   = null;
    this.tamanho = 0;    // lista criada = lista vazia
}
Cai na prova

Cauda e tamanho não são exclusivos da lista dupla — dava para colocá-los também na simples. O que define uma lista como duplamente encadeada é o nodo ter o campo anterior. O descritor de três atributos é a estratégia adotada neste material, não uma obrigação teórica.

07

Operações na lista duplamente encadeada

Toda operação agora precisa manter quatro coisas coerentes: os ponteiros proximo, os ponteiros anterior, o cabeca/cauda e o tamanho.

adicionarNoInicio()

public void adicionarNoInicio(int matricula, String nome) {
    Aluno novo = new Aluno(matricula, nome);
    if (this.getCabeca() == null)              // lista vazia:
        this.setCauda(novo);                    // o novo também é a cauda
    else
        this.getCabeca().setAnterior(novo);     // o antigo 1º aponta pra trás

    novo.setProximo(this.getCabeca());
    novo.setAnterior(null);                     // é o 1º: nada antes dele
    this.setCabeca(novo);
    this.setTamanho(this.getTamanho() + 1);
}

adicionarNoFinal()

public void adicionarNoFinal(int matricula, String nome) {
    Aluno novo = new Aluno(matricula, nome);
    if (this.getCauda() == null)               // lista vazia:
        this.setCabeca(novo);                   // o novo também é o cabeca
    else
        this.getCauda().setProximo(novo);       // o antigo último aponta pro novo

    novo.setAnterior(this.getCauda());
    novo.setProximo(null);                      // é o último: nada depois
    this.setCauda(novo);
    this.setTamanho(this.getTamanho() + 1);
}
Conceito-chave

Os dois métodos são espelhados: inserindo no início, o if testa o cabeca e ajusta a cauda; inserindo no fim, testa a cauda e ajusta o cabeca. O motivo é o mesmo nos dois: quando a lista está vazia, o nodo inserido é ao mesmo tempo o primeiro e o último.

Cai na prova

Diferença crucial para a lista simples: inserir no final aqui é imediato, sem while nenhum, porque a cauda já guarda o endereço do último nodo. Na lista simples era preciso varrer a lista toda.

removerAluno() — agora com quatro ajustes

public void removerAluno(int matricula) {
    Aluno AlunoAux = this.getCabeca();
    Aluno AlunoAuxAnterior = null;
    while (AlunoAux != null && AlunoAux.getMatricula() != matricula) {
        AlunoAuxAnterior = AlunoAux;
        AlunoAux = AlunoAux.getProximo();
    }
    if (AlunoAuxAnterior == null) {               // era o primeiro
        this.setCabeca(AlunoAux.getProximo());
        AlunoAux.setAnterior(null);
        this.setTamanho(this.getTamanho() - 1);
        return;
    }
    if (AlunoAux != null) {                       // qualquer outro
        AlunoAuxAnterior.setProximo(AlunoAux.getProximo());
        if (AlunoAux.getProximo() != null)          // não era o último?
            AlunoAux.getProximo().setAnterior(AlunoAuxAnterior);
        this.setTamanho(this.getTamanho() - 1);
    }
}

Removendo John de Paul ⇄ John ⇄ George: o proximo de Paul passa a ser George, e o anterior de George passa a ser Paul. Os dois sentidos precisam ser costurados — esquecer o anterior quebra a impressão invertida.

Pegadinha comum

O if (AlunoAux.getProximo() != null) existe porque, se o nodo removido era o último, não há nodo posterior para ajustar o anterior — chamar setAnterior() sobre null daria NullPointerException.

Impressão nos dois sentidos

// do início para o fim: parte do cabeca, anda pelo proximo
Aluno AlunoAux = this.getCabeca();
while (AlunoAux != null) AlunoAux = AlunoAux.getProximo();

// do fim para o início: parte da cauda, anda pelo anterior
Aluno AlunoAux = this.getCauda();
while (AlunoAux != null) AlunoAux = AlunoAux.getAnterior();

A impressão invertida é a demonstração mais direta da vantagem da lista dupla: numa lista simplesmente encadeada ela seria inviável sem recursividade ou uma estrutura auxiliar.

08

Comparativo e pontos de atenção

 Simplesmente encadeadaDuplamente encadeada
Campos do nodoinformação + proximoinformação + proximo + anterior
Atributos da listacabecacabeca, cauda, tamanho
NavegaçãoSó para frenteFrente e trás
Inserir no inícioImediatoImediato
Inserir no finalVarre a lista todaImediato (usa a cauda)
Saber o tamanhoPrecisa contarImediato (atributo tamanho)
Memória por nodoMenorMaior (um ponteiro a mais)
Conceito-chave

A lista dupla troca memória por velocidade e flexibilidade: gasta um ponteiro a mais em cada nodo e exige mais ajustes em cada operação, mas dá navegação nos dois sentidos e acesso imediato ao fim da lista.

Erros que aparecem em prova prática

  • Perder a lista: mexer no cabeca antes de guardar a referência do resto.
  • Esquecer o anterior: na lista dupla, ajustar só o proximo deixa a lista consistente numa direção e quebrada na outra.
  • Esquecer o tamanho: toda inserção soma 1 e toda remoção subtrai 1 — se um caminho do if não fizer isso, o descritor mente.
  • Condição de parada trocada: AlunoAux != null (varrer tudo) × AlunoAux.getProximo() != null (parar no último).
  • Remover de lista vazia: no código fornecido, chamar removerAluno() com a lista vazia cai no if (AlunoAuxAnterior == null) com AlunoAux valendo null e estoura NullPointerException. Um teste de lista vazia no início do método resolveria.

QQuais são as três situações avaliadas pelo removerAluno()?

Servem para navegar pela lista: AlunoAux aponta para o nodo avaliado e AlunoAuxAnterior sempre para o de trás. Se ao sair do laço AlunoAuxAnterior ainda for null, o laço não deu nenhuma volta — logo o nodo procurado era o primeiro.

QComo se remove todos os nodos da lista simplesmente encadeada? Por que funciona?

Uma única instrução: setCabeca(null). Perdida a referência do início, nenhum nodo é mais alcançável e o coletor de lixo do Java recolhe a corrente inteira.

QO que é o descritor da lista e quais seus três atributos?
clique para revelar
É o conjunto de atributos que a lista duplamente encadeada mantém atualizado: cabeca (primeiro nodo), cauda (último nodo) e tamanho (int com a quantidade de nodos).

QNuma lista duplamente encadeada, para onde apontam o anterior do primeiro nodo e o proximo do último?
clique para revelar
Ambos para NULL. São as duas "bordas" da lista — conhecendo o endereço de qualquer nodo, dá para varrê-la nas duas direções até bater em NULL.
→ Ver teoria: 06 · Lista dupla
QPor que o adicionarNoInicio() da lista dupla mexe na cauda quando a lista está vazia?
clique para revelar
Porque numa lista vazia o nodo inserido é ao mesmo tempo o primeiro e o último. O método espelhado faz o inverso: adicionarNoFinal() testa a cauda e ajusta o cabeca.
→ Ver teoria: 07 · Operações na dupla
QPor que inserir no final é rápido na lista dupla e lento na simples?
clique para revelar
A lista dupla mantém a cauda, que já guarda o endereço do último nodo — insere direto. A simples só tem o cabeca, então precisa de um while que varre a lista inteira até achar o último.
→ Ver teoria: 07 · Operações na dupla
QAo remover um nodo do meio de uma lista dupla, quantos ponteiros precisam ser ajustados? Quais?
clique para revelar
Dois: o proximo do nodo anterior passa a apontar para o posterior, e o anterior do nodo posterior passa a apontar para o anterior. Mais o tamanho, que é decrementado. Se o removido era o último, o segundo ajuste é pulado (não há nodo posterior).
→ Ver teoria: 07 · Operações na dupla
QComo se imprime uma lista de trás para frente? Por que isso é inviável na lista simples?
clique para revelar
Parte-se da cauda e caminha-se pelo getAnterior() até null. Na lista simples o nodo não guarda o anterior — só existe caminho para a frente, então não há como voltar sem recursividade ou estrutura auxiliar.
→ Ver teoria: 07 · Operações na dupla
